# ADR-001
# Contrato Oficial de Paginação do OSFlow

Status: APROVADO
Versão: 1.0
Data: 01/08/2026

---

## Objetivo

Definir o contrato oficial de paginação do OSFlow.

Este documento aplica-se a todos os módulos que apresentem listas de dados.

Exemplos:

- Radar
- Leads
- Imóveis
- Fluxo
- OLX
- Idealista
- Casa Sapo
- futuros providers

---

# Princípio 1

Repository nunca devolve rows da base.

Repository devolve sempre objetos do domínio.

Exemplo:

provider_leads

↓

mapProviderLeadToOpportunity()

↓

Opportunity

---

# Princípio 2

Repository conhece SQL.

Service não conhece SQL.

React não conhece SQL.

---

# Princípio 3

Repository é responsável por:

- filtros SQL

- paginação SQL

- ordenação SQL

- normalização dos dados

Nunca o Service.

---

# Princípio 4

Service apenas orquestra.

Exemplo:

Promise.all(

getSummary(),

getPage(),

getProviderRegistry()

)

e monta o Snapshot.

Nenhuma regra de negócio deverá ser duplicada.

---

# Princípio 5

Hook apenas controla estado.

page

pageSize

loading

reload()

Nenhuma lógica SQL.

---

# Princípio 6

React apenas apresenta.

A UI nunca executa:

slice()

sort()

filter()

sobre milhares de registros.

Toda paginação ocorre na base de dados.

---

# Snapshot Oficial

Todo módulo paginado deverá devolver:

{
    summary,

    pagination,

    data
}

---

summary

Contadores oficiais.

Nunca calculados pela UI.

Exemplo:

{

monitorizadas,

novas,

importadas

}

---

pagination

{

page,

pageSize,

total,

totalPages

}

---

data

Array contendo apenas a página solicitada.

Nunca o conjunto completo.

---

# Contrato do Repository

Todos os métodos deverão preservar o contrato público.

A implementação pode mudar.

O contrato não.

Exemplo:

listOpportunities()

↓

Opportunity[]

getPage()

↓

Opportunity[]

A única diferença permitida:

volume de dados.

---

# Ordem obrigatória de migração

Toda alteração seguirá esta ordem:

1.

Banco

↓

2.

Repository

↓

3.

Service

↓

4.

Hook

↓

5.

React

↓

6.

Remoção do legado

É proibido inverter esta sequência.

---

# Rollback

Cada etapa deverá permitir rollback independente.

Nenhuma microtarefa poderá depender de código ainda não homologado.

---

# Regra Final

Nenhuma otimização poderá alterar o contrato entre camadas.

Otimizações mudam implementação.

Nunca a interface pública.
